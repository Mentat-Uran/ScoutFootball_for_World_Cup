# ScoutFootball 产品与工程路线图

> 更新日期：2026-06-23。路线图描述方向和阶段门槛；可执行任务及完成状态以 `docs/TASKS.md` 为准。

## 1. 长期定位

ScoutFootball 的目标是本地优先、可复现、可解释的足球研究与球探决策平台。产品主线由五个闭环组成：数据与合规、评分与评估、球探决策、动作价值、战术演示。浏览器只承担只读分析和轻量本地交互；采集、训练、批处理和视频转码留在 Python/本地服务层。

成功标准不是页面数量，而是：同一数据快照可复现、结论带覆盖率和来源、人工判断可追踪、模型改动有同口径基线、静态版与 API 版行为一致。

## 2. 当前基线

- Pipeline、FastAPI、Streamlit、静态 Liquid Glass 前端和桌面打包链路已存在。
- 球探与动作价值导航已恢复。球探页读取 review queue/watchlist/shortlist，状态和备注保存在浏览器；动作价值页读取 xT/VAEP，并按分钟、赛事和模型筛选。
- 静态发布快照与 API 使用相同前端契约；纯静态服务器的 API 404 会回退到 `frontend/data/`。
- 当前主要边界：球探写入没有正式后端审计链；VAEP 部分产物只有 `player_id`、缺少稳定姓名映射；动作价值覆盖仅代表 StatsBomb Open Data 样本。

## 3. 分阶段计划

### 阶段 A：恢复后的稳定化（现在至 6 周）

目标：让现有能力可信、可测试、可发布。

1. 为球探和动作价值加入浏览器级 CI：API 在线、静态回退、空数据、字段缺失、移动端四类场景。
2. review queue 增加分页或虚拟列表，避免一次渲染 200+ 卡片；筛选状态写入 URL 或本地会话。
3. 建立前端 payload schema/version，导出静态数据时验证字段、数量、来源和更新时间。
4. 补 VAEP `player_id -> player_name/team/season` 实体映射；无法映射时继续显示 ID，并明确覆盖率。
5. 清理 README、TASKS、AGENTS、FRONTEND_STATUS、FRONTEND_SYNC 中的状态漂移，CI 增加关键断言。

退出门槛：关键视图无未捕获异常；API/静态快照契约测试通过；桌面和 760px 移动断点可用；文档与代码状态一致。

### 阶段 B：球探决策闭环（1 至 3 个月）

目标：从“只看榜单”升级到可审阅、可导出、可回灌的本地工作流。

1. 定义版本化 scouting workspace 文件：复核状态、备注、标签、快照 ID、操作者、时间戳和来源。
2. 支持 workspace JSON/CSV 导入导出、冲突检测、watchlist diff 和审阅摘要；默认仍不启用远程写入。
3. 将人工确认结果通过显式命令导入 `player_truth_labels.parquet`，模型预测字段与人工标签字段严格分离。
4. 增加按位置、联赛、原因、置信度、评分变化的队列切片，以及模型运行间 diff。
5. 报告页输出“需要人工判断的原因”，而不是只输出分数。

退出门槛：复核记录可 round-trip；每条人工标签可追溯到快照和来源；没有静默覆盖本地产物。

### 阶段 C：动作价值产品化（2 至 4 个月）

目标：把 xT/VAEP 从排行榜变成有覆盖边界的分析工具。

1. 加入球员、球队、比赛三级下钻；支持 pass/carry/shot、区域和时间段拆分。当前已交付 3 场跟踪样本的球员→比赛证据切片；全量、版本化比赛产物仍待完成。
2. 增加样本量、比赛数、分钟数、赛事覆盖和置信区间，不允许仅按 per-90 极值给强结论。
3. xT/VAEP 进入评分模型前，先做时间切分、缺失机制分析、同位置 baseline 和消融实验。
4. 战术板只接收带来源的样例热区；不把事件样本自动解释成战术建议。
5. 所有公开图表和导出保留 StatsBomb attribution 与数据快照标识。

退出门槛：实体映射稳定；关键聚合可复算；模型卡记录覆盖与偏差；加入评分后在同一 holdout 上有可解释增益。

### 阶段 D：统一产品壳与发布质量（3 至 6 个月）

目标：降低 Streamlit、静态前端、API 和桌面应用之间的状态漂移。

1. 明确主产品壳；短期继续维护静态前端，只有在路由、状态和测试复杂度超过阈值后才评估框架迁移。
2. 统一版本、健康检查、静态 manifest、迁移策略和离线提示。
3. 为 Windows/macOS 桌面包建立可重复构建、签名、升级和回滚验证。
4. 建立发布检查表：测试、数据 manifest、许可证、文档、截图、安装包、回滚说明。

### 阶段 E：空间、视频与协作研究（6 至 12 个月）

只在阶段 A-C 稳定并获得合规数据后启动：StatsBomb 360、Metrica/open tracking、possession threat、off-ball value、视频叠画。实时协作、云同步和公开分享默认不进入主线，除非先完成身份、权限、冲突和数据合规设计。

## 4. 工程决策门槛

- 新数据源：许可证、缓存边界、实体映射、失败模式和删除策略先于代码接入。
- 新模型：baseline、时间切分、指标、误差案例、模型卡和回滚方案必须齐全。
- 新前端能力：先定义 API/静态 JSON 契约、空状态、低覆盖状态、无障碍和移动行为。
- 新写入能力：必须有 schema 版本、审计字段、备份、冲突策略和导入回滚。
- 新依赖或框架：必须证明能减少长期复杂度，并给出迁移、构建体积和离线影响。

## 6. 通用完成定义

一个功能只有同时满足实现、自动化测试、浏览器验证、空数据与低覆盖行为、数据来源、文档同步和回滚/降级路径，才可以在 `TASKS.md` 标记完成。仅有 UI、仅有端点或仅有本地数据都不算完成。
